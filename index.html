RL-Optimized Source to Source Compiler Overview

            
RL-Optimized Source to Source Compiler is an end-to-end imperative source-to-source compilation framework paired with a tabular Reinforcement Learning Q-learning agent. The compiler translates a custom C-like procedural source language into rigorously optimized Python 3 source code.

            
Unlike conventional optimizing compilers that depend on fragile, hardcoded heuristics or fixed phase orderings, this system uses an autonomous RL agent that inspects intermediate Three-Address Code (TAC) and applies optimal sequences of program transformations to minimize instruction count and execution latency while preserving semantic equivalence.

            
    
              
  • Syntax Convention: C-like procedural syntax; statements terminate with semicolons (;); blocks are delimited by curly braces ({ }).
    • 
              
  • Dynamic Typing: Numerical literals are treated as double-precision floating point; strings are first-class immutable sequences.
    • 
              
  • Guaranteed Termination: Sandboxed execution engine with daemon thread isolation and a 5.0 s watchdog timer preventing CPU hangs or infinite loops.
    •

Formal Grammar Specification (EBNF)

            
The language syntax is formally specified below in Extended Backus-Naur Form (EBNF). The recursive descent parser processes tokens deterministically with LL(1) lookahead:


            

              
                

                  Non-Terminal
                  Production Rule (EBNF)
                

              
              
                

                  Program
                  { Statement } EOF
                

                

                  Statement
                  AssignStmt | IfStmt | WhileStmt | PrintStmt | ScanStmt | Block
                

                

                  AssignStmt
                  IDENTIFIER ( "=" | "+=" | "-=" ) Expr ";"
                

                

                  IfStmt
                  "if" "(" Expr ")" Block [ "else" Block ]
                

                

                  WhileStmt
                  "while" "(" Expr ")" Block
                

                

                  PrintStmt
                  "print" "(" Expr ")" ";"
                

                

                  ScanStmt
                  "scan" "(" IDENTIFIER ")" ";"
                

                

                  Block
                  "{" { Statement } "}"
                

                

                  Expr
                  LogicalOr
                

                

                  LogicalOr
                  LogicalAnd { "||" LogicalAnd }
                

                

                  LogicalAnd
                  Equality { "&&" Equality }
                

                

                  Equality
                  Relational { ( "==" | "!=" ) Relational }
                

                

                  Relational
                  Additive { ( "<" | "<=" | ">" | ">=" ) Additive }
                

                

                  Additive
                  Multiplicative { ( "+" | "-" ) Multiplicative }
                

                

                  Multiplicative
                  Unary { ( "*" | "/" | "%" ) Unary }
                

                

                  Unary
                  ( "!" | "-" ) Unary | Primary
                

                

                  Primary
                  NUMBER | STRING | IDENTIFIER | "(" Expr ")"
                

              
            

          


          
          

            
The 7-Stage Compilation Pipeline

            
Every source program flows sequentially through 7 decoupled compilation stages, each exposing verifiable intermediate states:


            

              
                

                  Stage
                  Phase Name
                  Responsibilities & Invariants
                

              
              
                

                  Stage 01
                  Lexical Analysis
                  DFA tokenizer converts raw UTF-8 source into a structured token stream with precise line and column coordinate tagging.
                

                

                  Stage 02
                  Syntax Parsing
                  Recursive descent LL(1) parser verifies formal grammar and generates an Abstract Syntax Tree (AST) with precedence climbing.
                

                

                  Stage 03
                  Semantic Analysis
                  Validates lexical scoping hierarchies, ensures variables are initialized prior to reference, and builds symbol scope chains.
                

                

                  Stage 04
                  Three-Address Code
                  Lowers the AST into linear quadruples with explicit control flow labels (L1..Ln) and virtual temporaries (t0..tn).
                

                

                  Stage 05
                  RL Optimization
                  A tabular Q-learning agent iteratively rewires and simplifies the TAC stream to minimize bytecode instructions.
                

                

                  Stage 06
                  Target Code Gen
                  Translates optimized TAC into clean, idiomatic Python code with zero-division guards and clean execution wrappers.
                

                

                  Stage 07
                  Runtime Execution
                  Runs target code inside a secure sandboxed thread with isolated stdin pipes, watchdog killswitches, and stdout capture.
                

              
            

          


          
          

            
Variables & Scoping

            
Variables are implicitly declared upon their first assignment. The semantic analysis stage builds a scoped symbol table that verifies variables are defined before they are referenced.

Expressions & Mathematics

            
Arithmetic expressions follow standard mathematical operator precedence (*, /, and % bind tighter than + and -):

            

              
a = 10;
b = 3;
print(a + b);
print(a - b);
print(a * b);
print(a / b);
print(a % b);

              

                
Output

7
30
3.3333333333333335

Division & Modulo Zero-Check Protection: To eliminate fatal runtime exceptions in critical execution loops, target code wraps divisions and modulos in zero-guard ternaries: (a / b if b != 0 else 0) and (a % b if b != 0 else 0).

    i += 1;
}

Reinforcement Learning Optimization Engine

            
The optimizer models program optimization as a Markov Decision Process (MDP) over the Three-Address Code intermediate representation. At each instruction index, the tabular Q-learning agent evaluates local opcode contexts and selects transformation actions:


            
    
              
  • State Representation: Fingerprint of surrounding instruction opcodes within a window of position ±1, combined with variable live-range status.
    • 
              
  • Action Space:
                
      
                  
    • constant_folding: Replaces expressions of known constants with precomputed scalar values.
      • 
                  
    • dead_code_elimination: Prunes assignments to variables that are overwritten before being read.
      • 
                  
    • common_subexpression: Deduplicates identical computations and reuses previously computed temporaries.
      • 
                  
    • algebraic_simplification: Simplifies identity operations such as x + 0, x * 1, and x * 0.
      • 
                  
    • loop_invariant_motion: Hoists computations independent of loop variables outside the loop header.
      • 
                
    
              
    • 
              
  • Reward Formulation:
                Reward = (+10 × removed_instructions) + (+5 × folded_constants) − (20 × code_growth)
              
    • 
              
  • Exploration vs Exploitation: The agent follows an ε-greedy policy with an exponential decay schedule (×0.99 per optimization pass) to balance discovering new rewrite patterns and exploiting proven reduction paths.
    • 
            

          


          
          

            
Security & Sandboxing Guarantees

            
    
              
  • Thread & Process Isolation: Target Python execution runs inside an isolated daemon thread with a strict 5000 ms watchdog. Infinite loops and recursive lockups are terminated automatically.
    • 
              
  • Namespace Scrubbing: Dangerous builtins including os, subprocess, open, eval, exec, sys, and all module import mechanisms (__import__) are stripped from the sandbox execution environment.
    • 
              
  • Safe Division: Every division operation compiles with a non-zero guard to guarantee immunity against unhandled ZeroDivisionError crash conditions.
    • 
              
  • Recursion Guard: The compiler raises the system recursion limit to 10 000 during AST analysis and restores baseline defaults immediately after completion.
    •
